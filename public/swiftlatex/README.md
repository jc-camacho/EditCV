# LaTeX engine files

EditCV compiles LaTeX in the browser with SwiftLaTeX's WebAssembly build of pdfTeX
(pdfTeX 1.40.21). Everything it needs lives in this folder and is served as static files,
so compilation makes **no requests outside the app's own origin**.

```
public/swiftlatex/
├── swiftlatexpdftex.js     # Web Worker (patched, see below)
├── swiftlatexpdftex.wasm   # pdfTeX compiled to WebAssembly
└── pdftex/                 # TeX bundle, generated by `npm run build:texlive`
    ├── manifest.json       # offset/length of each file in the archive + files the worker may request
    └── bundle.gz           # format, packages, TFM, Type 1, VF, enc and map files in one gzipped archive
```

The engine comes from the **PdfTeX engine** release at
https://github.com/SwiftLaTeX/SwiftLaTeX/releases. `PdfTeXEngine.js` from that release is **not**
needed: `src/latex/engine.js` talks to the worker directly.

## Worker patches

`swiftlatexpdftex.js` is modified so it works from a static bundle. If you replace it with a new
release, reapply these changes:

1. The default endpoint `https://texlive2.swiftlatex.com/` is removed (`self.texlive_endpoint=""`), and
   `self.texlive_files=new Set` is added.
2. `kpse_find_file_impl` and `kpse_find_pk_impl` return "not found" right away for any file
   missing from `self.texlive_files`. Static hosts often answer missing paths with `index.html`
   and a 200 status (SPA fallback), so the worker must never request files that are not there.
3. Downloaded files are saved under `fileid || reqname`, because static hosts don't send
   SwiftLaTeX's `fileid` header.
4. Two new commands:
   - `settexlivefiles {files}` sets the manifest.
   - `addtexfile {key, name, src}` preloads a file into the worker's cache. `src/latex/engine.js`
     downloads `bundle.gz` once and preloads every file with it, so the worker never has to fetch
     files one by one with synchronous requests (one network round trip each).

## Rebuilding the TeX bundle

Run this after changing a template's packages or fonts:

```bash
npm run build:texlive
```

It needs a local TeX Live as the source of the files (on Alpine:
`apk add texlive texmf-dist-latexrecommended texmf-dist-fontsrecommended`). Packages missing
from it go in `scripts/texlive-extra/`, which currently holds `enumitem.sty`. The script:

1. builds the format with this WASM engine, because a format only works with the pdfTeX binary
   that produced it;
2. compiles the sample CV and a document with every supported character in every template,
   recording each file pdfTeX reads;
3. packs those files into `bundle.gz` and writes `manifest.json`;
4. compiles everything again from the bundle alone, to prove it is complete.
